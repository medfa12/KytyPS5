## Findings requiring qualification

Opus proposes head-of-line blocking in shared queue1: a nonreturning Games item
action could prevent later Media work. This is plausible, not established by the
psn40 timing or unmatched addresses. The review did not read the saved stacks.
Earlier parent bounded stack inspection found no aligned UILib/Accessor.Db
addresses; that does not refute a wait or provide a reliable full unwind.

Its alternative four probes (UILib RunSynchronously entry/return and PUI
Resolve/Reject) omit an Execute/lookup observation in the same run. The suggestion
to join callback IDs from existing Execute records needs validation: psn40 did
not capture those IDs, and historical addresses cannot safely be reread later.
Queue identity, current task identity and request attribution also need an
evidence-backed decoder. Do not adopt the proposed set as a ready command.

The recommendation to inspect frame_margin/frame_offset is useful, but calling
them the likely next Netflix blocker is speculative. The actual failed waveform
was not logged. App/native evidence supports the F32 implementation; the next
live run must establish the values actually used.

The brief incorrectly called waveform0x12 float. Opus correctly identifies it as
signed16 PCM; float32 is0x18. The media agent independently corrected this in its
latest native-backed implementation before the review was retrieved.
